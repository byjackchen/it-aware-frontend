# Ohla Journey dashboard

The Operation navigation includes Ohla Journey with eight native pages: Headline, Resolution, Gaps, Journey, Timeline, Persona, Patterns and Audit. Chinese and English labels follow the application's existing language switch. A version selection is kept in browser session storage, so it affects only the viewer's tab. The native pages read the backend's versioned section endpoints through `/api/ohla-journey/[...path]`; entity tables use paged reads and full detail reads. The proxy forwards the existing `it_aware_access` cookie and does not expose a browser upload route.

Resolution has the original report's dimension grouping and filters for topic, subtopic, resolution requirement, request type, journey path, entry, persona, tenure, worker type, business group, country, and settled state. Its matrix recomputes rates, outcomes, escalation, recontact and timing from the selected report's fact rows; each number and outcome bar opens the corresponding journeys. Expanding a topic shows its subtopic rows with matching totals and detail links, plus T1–T7 timing. Journey and Persona also expose first-contact channel and journey region. Timeline exposes the same dimensions as Resolution. It defaults to the original report's weekly topic-by-period pie matrix; daily and monthly periods, topic-to-subtopic drilldown, stacked outcome bars, top 30 people, and local weekday/hour heatmap are also available. Each chart cell opens the exact matching journeys. Resolution and Timeline keep channel and region hidden by the agreed filter policy. `channel` is the first contact channel. `region` is the first known ticket caller region, falling back to the user's work region. The frontend sends the same active filters to the section summary and entity list; filtered counts and detail totals must match.

Gaps shows candidate-family composition, gap counts by topic and a ranked list with family and topic filters; every ranked item opens its evidence. Persona cards select a persona and immediately filter the journey and user lists. The card's user count, detailed patterns, habit-feature table and validation checks are full-report values, while the journey count reflects the current filters; the page labels this distinction. Patterns shows recurrence curves, all need and rule rows through searchable tables, verdict and generator filters, candidate pushes and rate/value backtests. Audit shows scope, lineage, all pipeline stages, quality gates, persona model checks and limits. Headline shows published aggregates and a term glossary without filters.

The backend import is a separate service-account-only API. Local Chrome testing on 2026-10-07 showed all eight sidebar entries, the version selector, language switching, multi-dimension Resolution filtering, and a 144/179 resolved cell opening exactly 144 journey records in r069. This was against an isolated local database and not a cloud deployment.
